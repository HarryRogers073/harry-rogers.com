Academic Abstract

Modern digital design validation demands rigorous verification routines to ensure silicon correctness before tape-out. However, educational projects and low-cost laboratories often lack automated, real-time Hardware-in-the-Loop (HIL) environments. Test benches are frequently limited to pure software simulation or manual button-pressing testing.

This dissertation project presents a highly modular, decoupled software-to-silicon verification framework. Written in Python, it bridges the gap by translating high-level test vectors (generated manually, programmatically, or via AI assistants) into raw byte streams. These streams are run directly on physical FPGA logic gates via serial channels. By comparing physical hardware responses against a software golden model in real-time, the system guarantees silicon correctness while outputting detailed logical telemetry.

1. Core Object-Oriented Architecture

To maintain runtime flexibility and allow hot-swappable hardware setups, the framework is built using clean Object-Oriented Design patterns. The core execution loop is completely decoupled from low-level communication channels and device packet serialisation through three primary abstract interfaces:

  • TestEngine (The Orchestrator): The central manager class. It reads test files, executes validation, handles timeouts, and reports results. It operates purely on high-level dictionaries.
  • DeviceProfile (The Translator): The abstract bridge mapping human-readable data (e.g. integer variables) to binary byte formats. Subclasses define signal bit widths, register space limits, and byte packing instructions.
  • CommDriver (The Operator): The abstract transport link managing physical connection channels (Serial, TCP/IP, USB). It handles raw byte sequences.

This composition layout means the manager remains unchanged if you swap the hardware interface or target device. You only replace the components in settings.

CORE CLASS COMPOSITION (CONCEPTUAL) 
class TestEngine:
    def __init__(self, driver: CommDriver, profile: DeviceProfile):
        self.driver = driver
        self.profile = profile

    def execute_loop(self, test_row: dict) -> bool:
        # Pack dictionary values into binary bytes
        tx_bytes = self.profile.pack_command(test_row)
        
        # Send bytes down physical connection channel
        self.driver.send_packet(tx_bytes)
        
        # Receive exact bytes response block from hardware
        rx_bytes = self.driver.receive_packet(self.profile.response_size)
        
        # Unpack binary response back to values dictionary
        result_dict = self.profile.unpack_response(rx_bytes)
        
        # Validate against expectations
        return self.verify(result_dict, test_row)

2. Writing custom Device Profiles

Every custom coprocessor or FPGA module requires a unique byte layout. To support a new system, write a subclass of DeviceProfile. You must define the signal inputs/outputs schema (names and bit-widths) and override pack_command and unpack_response.

Below is a concrete implementation template for an 8-bit MAC (Multiply-Accumulate) hardware accelerator:

profiles/mac_accelerator.py 
from core.interfaces import DeviceProfile

class MACAcceleratorProfile(DeviceProfile):
    device_name = "8-bit MAC Accelerator"
    description = "Custom multiplier-accumulator logic coprocessor module."
    author = "Harry Rogers"
    version = "1.0.0"

    # Define inputs (Name, Bit-Width)
    inputs = [
        ("Operand A", 8),
        ("Operand B", 8),
        ("Accumulate", 1)
    ]

    # Define outputs (Name, Bit-Width)
    outputs = [
        ("accumulator", 16),
        ("overflow", 1)
    ]

    command_size = 3   # 3 bytes transmitted (Opcode/A/B)
    response_size = 3  # 3 bytes returned (2-byte Accumulator, 1-byte Overflow)

    def pack_command(self, test_data: dict) -> bytes:
        # 1. Parse accumulate flag (binary command byte mapping)
        opcode = 0x01 if int(test_data.get("Accumulate", 0)) > 0 else 0x00
        
        # 2. Pack inputs matching register limits
        op_a = int(test_data.get("Operand A", 0)) & 0xFF
        op_b = int(test_data.get("Operand B", 0)) & 0xFF
        
        # Return exact binary sequence
        return bytes([opcode, op_a, op_b])

    def unpack_response(self, raw_bytes: bytes) -> dict:
        if len(raw_bytes) < 3:
            return {"accumulator": 0, "overflow": 1}
            
        # Unpack big-endian 16-bit accumulator value from bytes 0 & 1
        acc = (raw_bytes[0] << 8) | raw_bytes[1]
        ovf = raw_bytes[2] & 0x01
        
        # Return mapping dictionary for the grading engine
        return {
            "accumulator": acc,
            "overflow": ovf
        }

3. Writing custom Communication Drivers

Physical connections vary across test stations (e.g. Serial, TCP sockets, or register-level interface cards). Inherit from CommDriver to wrap your hardware channels. The driver must handle blocking byte transfers and connection state monitoring.

Below is an implementation template wrapping TCP/IP communication for remote FPGA boards:

drivers/tcp_driver.py 
import socket
from core.interfaces import CommDriver

class TCPDriver(CommDriver):
    def __init__(self, host: str = "192.168.1.100", port: int = 5000):
        self.host = host
        self.port = port
        self.sock = None
        self.is_connected = False

    def connect(self) -> bool:
        try:
            self.sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
            self.sock.settimeout(2.0) # Prevent indefinite connection blocking
            self.sock.connect((self.host, self.port))
            self.is_connected = True
            return True
        except Exception as e:
            print(f"[TCP Driver] Failed to connect to {self.host}:{self.port} -> {e}")
            self.is_connected = False
            return False

    def disconnect(self):
        if self.sock:
            self.sock.close()
        self.is_connected = False

    def send_packet(self, data: bytes):
        if not self.is_connected or not self.sock:
            raise ConnectionError("Driver is not connected to hardware channel.")
        self.sock.sendall(data)

    def receive_packet(self, num_bytes: int) -> bytes:
        if not self.is_connected or not self.sock:
            raise ConnectionError("Driver is not connected to hardware channel.")
        
        # Maintain blocking read loop until full block arrives
        buffer = bytearray()
        while len(buffer) < num_bytes:
            chunk = self.sock.recv(num_bytes - len(buffer))
            if not chunk:
                raise ConnectionAbortedError("TCP connection terminated by peer.")
            buffer.extend(chunk)
        return bytes(buffer)

5. CSV Schema & Robust Diagnostics

Test batches are uploaded as standard CSV spreadsheet files. To protect physical FPGAs from register collisions or value overflow states, the test engine executes a validation sequence before starting HIL execution.

The CSV columns are mapped dynamically to inputs and expected outputs. Input columns must match signal names in the profile. Expected outputs must be prefixed with Expected .

Column Template Value Mapping Verification & Safety Checking Rules
Operation String Mnemonic Opcode conversion validator. Flags error if operation is undefined.
[Input Name] (e.g. Operand A) Integer Value Bit-width limit checks. Emits warnings if value exceeds 2width - 1.
Expected [Output Name] Integer Value Used as the software golden model value to compare against physical hardware responses.

Verification Diagnostics Layer:

  • Empty Check: Logs an execution error and aborts if the queue contains a blank CSV file.
  • Zero-Divisor Warning: Emits warnings for division mnemonic operations when divisor inputs are 0, alerting you of potential FPGA hardware lockups.
  • Timeout Handling: If a communication error occurs or a packet is truncated, the driver catches the timeout, increments the failure counter, and recovers connection without crashing the application.
